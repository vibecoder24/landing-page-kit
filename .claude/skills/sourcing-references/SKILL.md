# Sourcing references

Claude's reference pool is the web's design canon: Apple, Linear, Kinfolk, Vitsoe. A page built only from it looks like every well-made startup site. The owner's own finds, from print, shops and objects they own, are what make the page theirs. This skill writes two things: a sourcing list the owner can take out into the world, and a note draft for every find that comes back.

## 1. The sourcing list: `references/SOURCES.md`

Written from the frozen brief, before the owner collects. One file, under 60 lines, in this order:

1. **Weak rows first.** Read the coverage table in `NOTES.md`. List the rows with no reference or a gap, and for each say what kind of thing would fill it. Everything below serves these rows.
2. **Four buckets**, four to six items each, each item with the one thing to photograph:
   - **The trade's own print:** the magazines, catalogues, monographs, instruction sheets and colour cards the buyer already reads
   - **Physical places:** shops, showrooms, job sites, the owner's own shelves. A phone photo, same light each time
   - **Adjacent crafts the buyer admires:** the fields the audience borrows taste from, not the product's own category
   - **Category defaults to avoid:** what every competitor page does, taken from the brief's positioning lines, so the owner recognises and skips them
3. **Queries per site**, for each search site the owner says they use: three to five queries, phrased for that site. Name the one query to avoid because it returns the category average.
4. **Stop rule:** eight finds, weak rows first.

## 2. The note draft, for every file that lands

When a screenshot or photo appears in `references/` without a row, draft the row and show it on the board (`make_board.py`). The owner corrects it, and the correction is the taste signal, so an owner's own words in a row are never rewritten. The row has exactly these parts:

| Part | Rule |
|---|---|
| **Take this specific thing** | One decision, one sentence, that transfers to a landing page. A book cover is not a page: "the title at 40% of the cover height" becomes a type-scale ratio |
| **Covers** | The coverage row it fills: hero, card, photography, type, tone, signature move, CTA or motif |
| **Don't take** | The thing in the same image that would pull against the brief |

If the image is spoiled (cookie wall, banner, cropped), the row says **recapture** and nothing else.

## Common mistakes

- A bucket with websites in it. If an item has a URL it belongs under queries.
- Two things in "Take this". Keep one; the other goes in a second row or in "Don't take".
- A note written from the category ("warm interiors photography") instead of from the image ("one lamp, side light, the room is in use").
- Filling the owner's rows for them. The draft waits; the file stays theirs.
- Asking about fonts or colours. That is Stage 2.
